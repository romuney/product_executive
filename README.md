# Product Executive Report

Аналитический отчёт по ресурсам и аллокациям в **продуктовой структуре**.
Не верхнеуровневый борт для руководителя, а рабочий инструмент HRBP,
руководителя продукта и всех, кому нужен ответ на два вопроса:

> Из кого сейчас состоит продукт — и как этот состав менялся.

Макет: HTML, без внешних библиотек, всё рисуется на голом SVG.
Данные синтетические и детерминированные.

## Открыть

- **Разработка:** открыть `index.html` — файлы подключаются по отдельности.
- **Единый файл:** `node build.js` собирает `index.standalone.html` —
  самодостаточный HTML без внешних зависимостей, его и отдают заказчику.
- **Проверки:** `node smoke.js` — 599 автоматических проверок, браузер не нужен.

## Почему это отдельный отчёт, а не вкладка в общем

В управленческой структуре человек принадлежит одному подразделению.
В продуктовой у него есть **аллокация** — процент занятости на продукте, —
и поэтому один человек одновременно живёт на нескольких продуктах.
Из одной этой сущности следует всё остальное:

- численность перестаёт быть однозначной: уникальных сотрудников меньше,
  чем строк «человек на продукте»;
- появляется движение, которого в управленческой структуре нет вовсе:
  вход и выход **с продукта** без увольнения, и изменение процента у того,
  кто с продукта не уходил;
- часть HR-метрик (текучесть, оценки ревью) к аллокации не привязывается
  в принципе: 70% человека нельзя «уволить». Для них есть режим
  «только основной продукт» — правило «один человек — один продукт».

**Сегмент — свойство человека, а не аллокации.** Сегмент считается по
максимальной аллокации внутри выбранного среза: кто стоит на 70% и 30%, тот
прямой ресурс, а не «прямой и парт-таймер сразу». Только так разбивка
складывается в число уникальных сотрудников точно и работает как легенда
главной метрики, а не как отдельная таблица с собственным итогом.

Смешать это с управленческим отчётом нельзя: получились бы две метрики
с одним названием и разными значениями.

## Структура отчёта

**Полка фильтров слева** — период и гранулярность (месяц / квартал / год),
дерево продуктов каталога, сегмент аллокации, «только основной продукт»,
профессия, грейд, локация, тип занятости. Фильтр применяется сразу,
всё состояние живёт в ссылке.

**Переключатель «Люди / Аллокации»** стоит над отчётом, потому что меняет
смысл всех чисел разом, а не содержимое одного блока.

**Вкладка «Ресурсы и движение»**

| Блок | Отвечает на вопрос |
|---|---|
| Карточка «Уникальные сотрудники» | Сколько людей в срезе и насколько это больше начала периода |
| Карточка «Сумма аллокаций» | Сколько ставок стоит команда |
| Карточка «Здоровье аллокаций» | В порядке ли данные: доля со ставкой ровно 100%, число проблемных и риска состава — детали по наведению |
| Карточки «Продуктов в срезе» и «Открытые квоты» | Сколько продуктов подтвердили состав, сколько позиций не закрыто |
| Динамика ресурсов и движения (слева, шире) | Сверху уровень — занято и открытые квоты, снизу движение, которое этот уровень меняет. Клик по легенде убирает серию |
| Состав команды (справа сверху) | Из кого состоит итог: каскад по сегментам аллокации. Клик по части фильтрует отчёт |
| Как изменилось за период (справа снизу) | Водопад: найм, вход, изменение аллокации, выход, отток |
| Трансформер | Те же метрики в разрезе плюс открытые квоты и укомплектованность, два уровня раскрытия |

Правая колонка читается сверху вниз как один сюжет: состав разбирает то
самое число, которым заканчивается водопад под ним. Высоту колонки задаёт
динамика слева, водопад забирает весь остаток — низ обеих колонок совпадает,
и серой пустоте взяться неоткуда.

**Вкладка «Трансформер»**

- *В динамике*: строки — до трёх вложенных разрезов, столбцы — периоды.
- *Матрица*: один разрез по строкам, другой по столбцам, фиксированный
  набор атрибутов.

**Вкладка «Сотрудники»**

Конец любой цепочки вопросов: «сколько людей» → «сколько пришло» →
**«а кто эти люди»**. Список наследует все фильтры отчёта и добавляет
событие за период и поиск. Клик по любому числу движения в трансформере
открывает список уже с наложенными фильтрами. Есть выгрузка в CSV.

## Четыре вида движения

| Событие | Что произошло |
|---|---|
| Найм на продукт | Человек новый и в компании, и на продукте |
| Вход на продукт | Уже работал в компании, но на этом продукте не стоял |
| Выход с продукта | Остался в компании, с продукта ушёл |
| Отток из компании | Аллокация закрылась вместе с увольнением |
| Изменение аллокации | С продукта не уходил, изменился процент. Только в режиме аллокаций |

Инвариант, который проверяется автоматически на каждом срезе и в каждой
строке любого разреза:

```
начало + найм + вход + рост аллокации − снижение − выход − отток = конец
```

## Файлы

```
index.html              каркас, порядок загрузки
styles.css              дизайн-система: токены и компоненты
data.js                 модель: люди, аллокации, квоты, списки сотрудников
draw.js                 рисовальный слой на голом SVG
ui.js                   общие компоненты: карточки, таблицы, тултип
screens/overview.js     вкладка «Ресурсы и движение»
screens/transformer.js  вкладка «Трансформер»
screens/people.js       вкладка «Сотрудники»
app.js                  состояние, полка фильтров, обработчики, выгрузка
build.js                сборка в один файл
smoke.js                автоматические проверки
SPEC.md                 требования и принятые решения
```

Слои читаются строго сверху вниз: данные → рисование → общие элементы →
экраны → приложение. Экран не пишет разметку сам — ни SVG-строк, ни `<table>`,
только сбор данных и вызовы общих элементов.

## Дизайн-система

Отчёт собран по дизайн-системе TeamPulse
([DESIGN_SYSTEM.md](https://github.com/romuney/TeamPulse/blob/main/Team%20Pulse/DESIGN_SYSTEM.md)):
токены скопированы целиком и не правлены, компоненты взяты оттуда же.
Что специфично для этого отчёта:

- **Цвет здесь почти всегда категория, а не оценка.** Гамма движения
  (бирюзовый приход, сиреневый уход) — виды потока. Зелёный и красный
  появляются только там, где оценка действительно есть: верификация
  аллокаций, укомплектованность квот, здоровье аллокаций.
- **Заливка ячейки в трансформере** показывает величину внутри столбца.
  У запасов её нет: соседние месяцы отличаются на проценты, и таблица
  заливается ровным пятном ни о чём.
- **Открытая квота — белая часть бара**, а не соседний бар: вместе
  с занятой частью они дают план по продукту.
- **Скругление кодирует «обрезана марка или закончилась».** Край,
  упирающийся в ось или в соседний сегмент стопки, — ровный. Скруглён
  только край, которым марка заканчивается: в стопке это внешний край
  плеча, и он переезжает сам, когда серию выключают в легенде. Марка,
  висящая в воздухе целиком (шаг водопада, часть разложения), скруглена
  со всех сторон.
- **Категории идут по вертикали, а не по горизонтали.** Категории на
  оси X читаются как время: глаз видит в «прямые → шаренные → частичные»
  последовательность, которой нет.
